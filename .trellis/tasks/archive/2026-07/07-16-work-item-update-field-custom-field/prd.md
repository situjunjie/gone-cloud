# 工作项快捷更新适配自定义字段

## Goal

完善 `PUT /project/work-item/update-field` 对自定义字段的快捷更新能力，使调用方可以基于工作项 Schema 更新一个或多个自定义字段，同时保证未指定字段及其历史值不受影响。

## Background

- 当前接口已经通过 `field = "custom:<fieldId>"` 识别自定义字段，并调用
  `WorkItemCustomFieldValueService#updateValue`。
- 当前 `updateValue` 会先读取工作项全部自定义字段，再调用 `saveSnapshot` 重建整份快照。
- 该实现会重新校验所有未修改字段：若工作项保留已禁用字段/选项的历史值，更新另一个字段也可能失败，与“禁用对象保留历史值、快捷更新只修改指定字段”的既有契约不一致。
- 同一请求包含多个自定义字段时，当前实现会重复读取和重建整份快照，缺少批量校验与一次性局部写入。
- `ProjectWorkItemServiceImplTest` 当前没有覆盖 `/update-field` 的自定义字段路径。

## Requirements

### 快捷更新语义

- 外部请求继续使用统一字段列表协议，自定义字段名为 `custom:<fieldId>`；不新增独立的
  `customFieldValues` 快捷更新属性。
- 一个请求可以同时更新内置字段和一个或多个自定义字段，整体保持同一事务。
- 自定义字段更新必须是局部 Patch：只替换请求中指定的字段值，未指定字段保持不变。
- JSON `null` 或字段类型定义的空值用于清空可选自定义字段；清空必填字段必须失败。
- 目标字段仍需校验 scope、项目归属、适用分类、启用状态、字段类型、用户和选项归属/启用状态。
- 未指定的已禁用字段或已禁用选项历史值不得阻塞其他字段的快捷更新，也不得被静默删除。
- 多个自定义字段必须先完成批量解析和校验，再一次性替换目标字段，避免逐字段重建整份快照。
- 重复的自定义字段编号、非法 `custom:` 编码或非法值必须在写入前失败。

### 兼容与边界

- 保持 `/update-field` 现有权限、事务和内置字段更新行为。
- 不改变工作项创建和完整更新的 `customFieldValues` 快照语义。
- 不修改数据库表结构；局部替换复用现有字段值表和选择值关联表。
- 本任务不放宽工作项所属项目迁移规则。
- 工作项分类与自定义字段同时变更时，沿用现有分类变更校验；是否允许通过同一请求清理不再适用的旧字段值不在本任务范围内。

## Acceptance Criteria

- [x] `/update-field` 可以更新单个和多个自定义字段，并与同请求内置字段更新保持事务一致。
- [x] 请求中未指定的自定义字段值保持不变。
- [x] 未指定的禁用字段/禁用选项历史值不会阻塞其他字段更新，也不会被删除。
- [x] 清空可选字段成功，清空必填字段失败。
- [x] 非法字段编号、重复字段、跨项目字段、不适用分类、禁用目标字段/选项和类型错误均被拒绝。
- [x] 自定义字段批量更新只执行一次目标字段替换，不逐字段重建完整快照。
- [x] 新增 Service 单元测试覆盖请求解析、批量委托、历史禁用值保留和局部清空。
- [x] project server 聚焦测试和全量测试通过。
