# 项目工时管理设计与实现

## Goal

在 `project` 模块中建立独立、可追溯的工时实体，使项目成员能够围绕工作项登记预估工时和实际工时，查询登记明细，并按明确口径获得工时汇总，为工作项进度、迭代容量和后续项目报表提供真实数据来源。

## Background And Confirmed Facts

- 工时是独立实体，不作为工作项上的单一附属字段实现。
- 工时分为“预估工时”和“实际工时”两种类型。
- 每条工时记录需要关联工作项，并包含工时数、工作类别、工作描述和工时负责人。
- 工作类别使用系统字典，首批固定提供：设计、研发、测试、文档、其他。
- 当前 `proj_work_item` 已存在 `estimated_workload` 字段，工作项保存和响应接口也暴露 `estimatedWorkload`；由于项目尚未上线，本任务直接删除该字段及相关接口入口，不保留兼容或迁移逻辑。
- 当前迭代列表已有 `capacityHours`，但 `usedHours` 固定返回 `0.0` Mock；本任务使用实际工时汇总替换该 Mock。
- 当前项目域已有系统菜单权限和项目角色权限双层校验，工时接口需要沿用这一安全边界。
- 当前工作项允许变更所属项目，已有评论时会阻止跨项目移动；工时采用相同的历史归属保护规则。
- 当前仓库是后端项目；本任务规划后端数据模型、SQL、接口、权限和测试，不包含前端页面实现。

## Requirements

### R1. 独立工时实体

- 新增项目工时实体及持久化表，每条记录唯一关联一个有效工作项。
- 工时记录至少包含：工时类型、工时数、工作类别、工作描述、工时负责人、工作日期，以及系统通用的创建、修改、逻辑删除、租户字段。
- 工时类型必须区分预估工时和实际工时，并由后端进行固定值校验。
- `workDate` 对实际工时必填，表示实际发生工作的日期；对预估工时可空，填写时表示计划工作的日期。
- 实际工时的时间范围查询和汇总必须使用 `workDate`，不能使用记录创建时间替代，以支持事后补录和修正。
- 工时数单位为小时，不得为负，最多保留两位小数，单条上限为 `99999999.99`。
- 工时负责人必须是工作项所属项目的有效项目成员。

### R2. 工作类别系统字典

- 在项目字典初始化 SQL 中新增工时工作类别字典。
- 字典项包括：设计、研发、测试、文档、其他；后端保存时校验字典值有效且启用。
- 字典编码和值需要稳定，允许后续通过系统字典维护展示信息，但不得改变既有记录语义。

### R3. 工作项关联工时

- 支持在指定工作项下新增、修改、删除和查询工时记录。
- 查询工作项时能够获得该工作项的预估工时合计和实际工时合计，避免前端自行拉取全部明细后求和。
- 工作项不存在、已删除、跨项目引用或负责人不属于该项目时，登记失败且不产生脏数据。
- 工作项存在任何未删除工时记录时，禁止将工作项移动到其他项目；用户需要先删除全部工时记录后再移动，避免历史项目归属、负责人资格、权限和汇总口径失真。
- 删除工作项时，在同一事务内逻辑删除该工作项关联的全部工时记录，再逻辑删除工作项；业务查询和汇总不再返回这些工时，数据库审计字段仍保留。

### R4. 工时登记明细

- 提供分页明细查询，至少支持按项目、工作项、工时类型、工作类别和工时负责人筛选。
- 明细响应包含工作项基本标识、工时类型、工时数、工作类别、工作描述、工作日期、负责人和审计时间。
- 明细查询遵守租户隔离、系统菜单权限、项目成员边界和项目角色权限。

### R5. 工时汇总

- 提供后端聚合查询，不通过加载全部明细后在应用层求和。
- 汇总至少分别返回预估工时合计和实际工时合计，不混合两种语义。
- 实际工时的时间范围筛选以 `workDate` 为口径；预估工时未填写 `workDate` 时不应伪造计划日期。
- 首期汇总限定在单个项目内，支持按迭代、工作项、工时负责人、工作类别、工时类型和工作日期范围筛选。
- 首期汇总返回预估工时总计和实际工时总计，并支持按工作项、负责人、工作类别、迭代进行单一维度分组；一次请求不组合多个分组维度。
- 日期范围筛选预估工时时，只统计填写了 `workDate` 且日期位于范围内的记录；未填写计划日期的预估记录仅参与不带日期范围的汇总。
- 首期不提供多维透视、按日趋势或跨项目汇总。
- 首期将迭代 `usedHours` 改为迭代内工作项关联的实际工时合计，并替换当前固定 `0.0` Mock；未登记实际工时时返回零。

### R6. 权限与审计

- 工时查询、新增、修改、删除使用独立且语义明确的系统菜单权限和项目角色权限，不复用无关权限掩盖边界。
- 新增项目权限 `WORKLOG_QUERY`，普通参与人角色默认拥有但不强制保留；项目管理员可以从特定角色移除。
- 拥有 `WORKLOG_QUERY` 的用户可以查看项目内全部工时明细和汇总；首期不实现仅查看本人记录的行级查询模式。
- 普通项目成员拥有 `WORKLOG_CREATE` 时，只能为自己登记工时，工时负责人固定为当前登录用户。
- 拥有项目角色权限 `WORKLOG_MANAGE` 的用户可以为工作项所属项目内的任意有效成员代填工时，并管理其他成员的工时记录。
- 预估工时和实际工时采用相同的负责人及代填规则。
- 代填记录同时保存工时负责人和系统审计创建者，两者不得互相替代，以便追溯实际归属与操作来源。
- 工时负责人可以修改和逻辑删除自己的记录；拥有 `WORKLOG_MANAGE` 的用户可以修改、逻辑删除项目内任意工时记录。
- 首期不设置修改或删除时间窗口，也不因工作项或迭代状态自动锁定工时记录。
- 工时记录创建后，所属工作项和工时类型不可修改；填错时应逻辑删除后重新登记。
- 工时数、工作类别、工作描述和 `workDate` 可以修改；只有 `WORKLOG_MANAGE` 可以变更工时负责人，且新负责人仍须是项目有效成员。
- 首期不新增业务版本表或审批历史；使用系统审计字段和操作日志追踪变更。
- Service 层必须根据持久化的工作项和工时记录反查真实 `projectId` 后复核权限，不能信任调用方传入的项目归属。
- 修改和删除不得改变工时记录所属的租户、项目或工作项归属。

### R7. 兼容与数据一致性

- 新工时实体是预估工时和实际工时的唯一权威来源。
- 删除 `proj_work_item.estimated_workload` 数据库字段，以及工作项 DO、保存请求、响应、字段更新、查询条件和变更记录中对应的 `estimatedWorkload` 能力；项目尚未上线，不提供旧字段兼容或数据迁移。
- 工作项需要展示预估工时合计时，只读取新工时实体的聚合结果。
- 迭代列表 API 保持现有响应结构，并以新实体的实际工时聚合替换 `usedHours` Mock。
- 汇总结果应排除逻辑删除记录，并与明细筛选口径一致。

## Acceptance Criteria

- [ ] AC1: 可以为有效工作项登记预估或实际工时，保存工时数、工作类别、描述、负责人和工作日期；实际工时缺少 `workDate`，或请求包含非法类型、非法字典值、负数工时、无效工作项、非项目成员负责人时均被拒绝。（R1、R2、R3）
- [ ] AC2: 普通登记者只能为自己新增工时，拥有 `WORKLOG_MANAGE` 的用户可为有效项目成员代填；代填记录能区分工时负责人与实际创建者，且任何请求都不能越权访问其他项目、租户或工作项的数据。（R3、R6）
- [ ] AC3: 负责人可修改和逻辑删除自己的记录，`WORKLOG_MANAGE` 可管理项目内全部记录；更新不能改变所属工作项或工时类型，只有 `WORKLOG_MANAGE` 可以变更负责人。（R3、R6）
- [ ] AC4: 拥有 `WORKLOG_QUERY` 的用户可以分页查询项目内全部工时明细，并按项目、工作项、类型、类别和负责人筛选；无该权限时拒绝访问，返回记录与分页总数准确。（R4、R6）
- [ ] AC5: 可以在单个项目内按迭代、工作项、负责人、工作类别、工时类型和工作日期范围筛选汇总，返回预估与实际工时总计，并可按工作项、负责人、工作类别或迭代进行单维度分组；结果与同条件下未删除明细之和一致。（R5、R7）
- [ ] AC6: `proj_work_item.estimated_workload` 及工作项接口、查询、快捷更新和变更记录中的旧 `estimatedWorkload` 能力被删除；工作项的 `estimatedHours`、`actualHours` 均来自新工时实体。（R3、R7）
- [ ] AC7: `project_worklog_category` 系统字典包含设计、研发、测试、文档、其他五项，并可被前端通过既有字典 API 获取。（R2）
- [ ] AC8: 迭代 `usedHours` 返回迭代内工作项的实际工时合计，不再固定为 `0.0`；未登记工时时返回零。（R5）
- [ ] AC9: 新增数据访问、Service、Controller 和聚合逻辑具有覆盖正常、边界、权限归属和逻辑删除口径的聚焦测试。（R1-R7）
- [ ] AC10: 工作项存在未删除工时记录时，全量更新和快捷字段更新都拒绝跨项目移动；无工时记录时保持现有移动行为。（R3、R7）
- [ ] AC11: 删除工作项时在同一事务内逻辑级联删除其全部工时记录，操作成功后明细和汇总均不再包含这些记录，且任一步骤失败时整体回滚。（R3、R7）

## Out Of Scope

- 前端页面、图表和交互实现。
- 审批流、计费单价、成本金额、加班规则、节假日和考勤联动。
- 自动计时器、第三方工时系统同步和批量导入导出。
- 扩展到项目外对象或不关联工作项的通用工时。
