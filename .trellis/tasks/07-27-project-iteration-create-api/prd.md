# 项目迭代创建接口

## Goal

为 `project` 模块提供项目迭代创建接口，使前端“新建迭代”表单能够在指定项目下创建迭代记录。

## Background

- 前端表单包含：迭代名称、迭代负责人、开始日期、结束日期、工时容量（推荐 h）、迭代描述。
- 请求还需携带页面隐藏字段 `projectId`。
- 仓库已存在 `proj_sprint` 表、`ProjectSprintDO` 和 `ProjectSprintMapper`，尚未发现迭代 Controller/Service 创建链路。

## Requirements

- 新增管理员端项目迭代创建接口。
- 请求参数覆盖 `projectId`、迭代名称、负责人、开始日期、结束日期、工时容量和描述；其中 `projectId`、迭代名称和负责人必填，其余字段可空。
- 迭代名称最长 50 个字符，描述最长 500 个字符。
- 开始、结束日期按前端日期选择器的自然日语义传输和保存；两者同时存在时结束日期不得早于开始日期。
- 工时容量可空；非空时必须大于等于 0，最多保留 1 位小数，并支持 `7.5h` 这类输入；使用 `decimal(10,1)` 存储。
- 对表单必填项、长度、容量数值和日期关系进行服务端校验。
- 新建迭代应使用系统约定的初始状态，并归属请求指定项目。
- 负责人必须是目标项目的有效成员。
- 目标项目必须存在且未归档。
- 创建成功返回迭代编号。
- 创建接口沿用系统权限与项目内权限双层校验，并为迭代创建定义语义明确的权限点。
- 项目内权限使用 `SPRINT_CREATE`；管理员天然拥有，自定义角色可配置，普通参与人默认不拥有。
- 系统权限使用 `project:sprint:create`。
- 接口沿用 `project` 模块现有异常码、VO、Service 和 Mapper 分层约定。
- 为现有 `proj_sprint` 表补充工时容量和描述字段，并同步全量建表 SQL 与增量迁移 SQL。

## Acceptance Criteria

- [x] 合法请求可创建一条字段完整、项目归属正确的迭代记录，并返回其编号。
- [x] 缺少必填字段、字段超长或结束日期早于开始日期时，请求被拒绝且不写入数据。
- [x] 负责人不是目标项目成员、项目不存在或项目已归档时，请求被拒绝且不写入数据。
- [x] 无权访问目标项目的用户不能创建迭代。
- [x] 普通参与人默认不包含 `SPRINT_CREATE`；管理员或显式授予该权限的自定义角色可通过项目内权限校验。
- [x] 全量建表脚本和已部署数据库的增量迁移脚本均包含新字段。
- [x] 创建行为具备覆盖成功和主要失败分支的自动化测试。

## Out of Scope

- 迭代查询、更新、删除、归档和状态流转接口。
- 前端表单开发。
- 修改工作项与迭代的关联逻辑。
