# DevOps 变量组

## Goal

为 DevOps 提供可复用的变量组配置能力。变量组按全局、应用、应用某个环境三级作用域保存，变量正文使用纯文本，每行一个 `KEY=VALUE`，并在流水线运行时按作用域合并生效。

## Background

- DevOps 后端位于 `yudao-module-devops/yudao-module-devops-server`，已有应用、环境、应用环境关系和流水线领域。
- 持久化遵循 `TenantBaseDO`、`BaseMapperX`、`sql/<engine>/` 脚本约定，业务数据默认租户隔离。
- 当前没有变量组实体、控制器或专用变量组解析服务；现有流水线已有统一 `PipelineVariableResolver`。

## Requirements

1. 变量组具备名称、作用域、关联应用/应用环境（按作用域必填）、变量文本、启用状态、备注及审计字段。
2. 变量文本服务端校验：每个非空行必须是 `KEY=VALUE`；KEY 使用环境变量风格（字母、数字、下划线，且不以数字开头）；允许 VALUE 为空并保留第一个等号后的全部文本；拒绝重复 KEY，并提供行号错误。
3. 提供管理端分页查询、详情、新增、修改、删除接口，遵循现有 REST、`CommonResult`、`@PreAuthorize` 和错误码规范。
4. 校验作用域关联对象存在且可用；全局作用域不得携带应用或应用环境；应用环境作用域必须引用有效的应用环境关系。
5. 同租户同作用域下变量组名称唯一；删除采用逻辑删除；更新重新校验作用域和文本。
6. 提供按运行上下文读取有效变量的服务，并注入流水线运行时：按“全局 → 应用 → 应用环境”合并，后者覆盖前者；系统保留运行变量不可被覆盖。
7. 变量值按普通文本处理，不在日志、异常、审计内容或运行结果 JSON 中回显；本期不引入 secret 类型或加密存储。

## Acceptance Criteria

- 能创建三种作用域的变量组，非法作用域组合被拒绝。
- `A=1\nB=a=b\nEMPTY=` 可保存并读取；重复 KEY、非法 KEY、缺少 `=` 的行保存失败并指出行号。
- 分页列表支持名称、作用域、关联对象、启用状态查询；详情返回原始文本；逻辑删除后不出现在有效列表。
- 同租户同作用域同名创建失败。
- 流水线运行上下文返回按全局→应用→应用环境优先级合并后的键值，同名覆盖和保留键保护有单测。
- DevOps 模块编译、变量组及流水线回归测试通过，`git diff --check` 通过。

## Out of Scope

- 前端页面实现。
- 变量加密、secret 掩码、版本发布、审批、导入导出。
- `${VAR}` 之外的复杂表达式解析。

## Key Decisions

- 本期直接接入流水线运行时，变量组管理完成后即可被流水线 `${VAR}` 解析使用。
- 作用域内多个变量组按 id 升序合并，后加载组覆盖同名键；系统运行变量在变量组之后写入，不能被覆盖。
